# Резервная копия и восстановление SQLite

Команда относится только к настроенной базе проекта `tournament`. Она не меняет `.env`, данные источника и другие проекты. Перед применением миграций и в конце дня турнира создавайте отдельную копию; храните хотя бы одну проверенную копию на другом носителе. Автоматическое расписание и удаление старых копий не включены.

## Создать копию

Из каталога проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe manage.py backup_database
```

Команда читает фактические `DATABASES['default']` из настроек, поэтому учитывает выбранную рабочую или демонстрационную базу. Итоговый путь выводится в консоль. По умолчанию это `.local/backups/<имя-базы>-<UTC-время>-<случайный-суффикс>.sqlite3`.

Для конкретного **нового** имени:

```powershell
.\.venv\Scripts\python.exe manage.py backup_database --output '.local/backups/before-tournament.sqlite3' --timeout 60
```

`--database` выбирает существующий alias Django, а не путь. `--timeout` допускает 1–300 секунд, по умолчанию 30. Исходный файл должен существовать; in-memory базы и URI-настройки не поддерживаются. Команда не перезаписывает существующие файлы, в том числе исходную базу. На нехватку места, блокировки сверх таймаута, повреждение или невозможность безопасной публикации она отвечает ошибкой и не публикует готовую копию.

Снимок создаётся через [SQLite Online Backup API](https://sqlite.org/backup.html), доступный как [Python `Connection.backup`](https://docs.python.org/3/library/sqlite3.html#sqlite3.Connection.backup). Он учитывает подтверждённые данные WAL; копирование только основного файла работающей базы обычным `Copy-Item` для этого не используется. Источник открыт в режиме `mode=ro`; результат проверяется через [PRAGMA integrity_check](https://sqlite.org/pragma.html#pragma_integrity_check). Это проверка структуры SQLite, а не гарантия правильности бизнес-данных.

После проверки и сброса данных на диск готовое имя создаётся атомарно без перезаписи через hard link; временное имя удаляется. Нужна файловая система с поддержкой hard links (обычный локальный NTFS подходит). Для неподдерживаемого носителя сначала создайте копию локально, затем перенесите уже завершённый файл. После аварийного выключения может остаться `.sqlite-backup-*.partial`: это не готовая копия, не используйте её для восстановления.

## Проверить восстановление в новом файле

Проверку можно выполнить без запуска сайта, бота и без изменения активной базы. В следующем примере замените `$backupPath` на **существующий путь из успешного вывода команды**. Путь восстановления должен быть новым:

```powershell
$backupPath = (Resolve-Path -LiteralPath '.local/backups/before-tournament.sqlite3').Path
$restoredPath = Join-Path (Get-Location) '.local/tournament-restored-check.sqlite3'
$previousDatabasePath = $env:DATABASE_PATH
try {
    $env:DATABASE_PATH = $backupPath
    .\.venv\Scripts\python.exe manage.py backup_database --output $restoredPath
    if ($LASTEXITCODE -ne 0) { throw 'Не удалось подготовить проверенную восстановленную копию.' }
    $env:DATABASE_PATH = $restoredPath
    .\.venv\Scripts\python.exe manage.py showmigrations --plan
    if ($LASTEXITCODE -ne 0) { throw 'Проверка схемы восстановленной копии не прошла.' }
} finally {
    if ($null -eq $previousDatabasePath) {
        Remove-Item Env:DATABASE_PATH -ErrorAction SilentlyContinue
    } else {
        $env:DATABASE_PATH = $previousDatabasePath
    }
}
```

`showmigrations --plan` не применяет миграции. При необходимости просмотра копии запускайте приложение отдельно с её `DATABASE_PATH`; не запускайте на ней `run_bot`: очередь уведомлений в копии также восстановлена и может повторно отправить старые сообщения.

## Вернуть восстановленную базу в эксплуатацию

1. Остановите сайт и `run_bot`, чтобы пользователи не записывали данные во время переключения. Сохраните резервную копию текущего состояния, если файл ещё читается.
2. Подготовьте **новый** восстановленный файл описанным выше способом. Не затирайте старую базу и её WAL/SHM-файлы.
3. Проверьте дату снимка, схему, команды, банковские номера, журнал проверок и последние платежи. Снимок не содержит изменений после момента его создания; сверку реальных поступлений после этой даты выполняет кассир.
4. Только после проверки измените `DATABASE_PATH` в конфигурации запуска на новый проверенный файл и запустите сайт. Эта инструкция не выполняет переключение автоматически.
5. Перед запуском бота проверьте восстановленную очередь и состояние его обработанных сообщений. Не очищайте историю платежей ради устранения повторов. Сначала установите, какие действия происходили после снимка.

Копия содержит данные участников, игровые привязки, сессии и финансовую историю. Не публикуйте её и не помещайте в общедоступный каталог; доступ к каталогу копий должен быть только у ответственных лиц. SQLite-копия не включает `.env`, исходный код и документы — их восстановление организуется отдельно.

## Автоматическая проверка

```powershell
.\.venv\Scripts\python.exe manage.py test arena.tests.test_backup_database
```

Тесты работают исключительно во временном каталоге: проверяют восстановление данных, аудита и ограничений; WAL с незавершённой транзакцией; запрет перезаписи; конфликт имени во время публикации; ошибочный источник; таймаут и безопасную очистку временных файлов. Рабочая и демонстрационная базы при этом не копируются и не изменяются.
