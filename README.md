# CQC Tournament

Публичная тестовая версия: **https://cqc-tournament.vercel.app**. Сайт на Vercel, отдельная PostgreSQL-база в Supabase, Telegram работает через webhook. Реальные взносы отключены. [Размещение, доступ организатора и ограничения](docs/VERCEL_DEPLOYMENT.md).

Проведение матчей: готовность капитанов, приватное лобби, обращения судье, технические поражения, исправления с историей и защита устаревших форм. [Инструкция](docs/MATCH_DAY.md). Уведомления доступны в кабинете; фоновая отправка событий Telegram включается отдельно. [Уведомления](docs/EVENT_NOTIFICATIONS.md).

Отдельный локальный сайт турнира. Проект `cqcstore` не изменяется. Python 3.13, Django 5.2 LTS, SQLite, Waitress; адаптивные страницы на русском. Сайт и Telegram-бот используют одну базу.

## Открыть локально

Сейчас на локальном адресе включён **тестовый турнир с открытой регистрацией**. Вход и сохранённый игровой профиль перенесены в отдельную базу `.local/tournament-demo.sqlite3`. Можно создавать команды и проверять взносы в панели организатора; ссылки Kaspi отключены, переводы не требуются, тестовые платёжные карточки кассиру не отправляются. Telegram-вход и поиск ника работают. Условия 5 + 1, BO3/BO5 и демонстрационные даты заданы только для теста, не как утверждённый регламент.

Переключение режима сохраняет обе базы. Остановите сайт и бота через `stop.ps1`, выполните `.\.venv\Scripts\python.exe scripts/demo_mode.py off` для реального черновика или `on` для теста, затем `start.ps1`. Новые тестовые команды и взносы не попадут в реальный турнир. Скрипт также переносит текущую позицию чтения Telegram, чтобы старые сообщения не обрабатывались повторно.

Адрес: http://127.0.0.1:8000/

Этот адрес и скопированные с него приглашения работают только на компьютере, где запущен сайт. Для локальной проверки разных ролей используйте отдельные профили браузера на этом компьютере. На телефоне `127.0.0.1` означает сам телефон: для приглашения других игроков нужен доступный им адрес сайта. Telegram-вход с возвратом в исходный браузер не делает локальный сайт доступным по сети.

Кабинет организатора: http://127.0.0.1:8000/organizer/

Логин и сгенерированный пароль находятся в `.local/admin-access.txt`. Файл исключён из Git. Бот: https://t.me/cqc_tournamentbot ; единственный кассир — `855341070`.

Первый запуск из PowerShell в папке проекта:

```powershell
.\setup.ps1
.\start.ps1
```

Повторный запуск: `start.ps1`. Остановка процессов этого проекта: `stop.ps1`. Скрипты запускают сервер и бота скрыто, журналы лежат в `.local/`. После перезагрузки компьютера нужен повторный запуск.

Ручной запуск вместо `start.ps1` — два отдельных терминала:

```powershell
.\.venv\Scripts\python.exe server.py
.\.venv\Scripts\python.exe manage.py run_bot
```

Не запускайте второго получателя Telegram-обновлений. Старый `scripts/telegram_bot.py run` был только временным этапом привязки и больше не используется. Команды `inspect`, `configure`, `set-photo` этого скрипта оставлены для обслуживания профиля.

## Что работает

- Страница турнира, правила, фонд, сроки и параметры состава.
- Вход/регистрация через Telegram; привязка Telegram к существующему аккаунту с паролем. Пароль остаётся для организатора и старых учётных записей.
- Игровой профиль MLBB: участник вводит Game ID и Server ID, получает ник автоматически и подтверждает найденный аккаунт. Ручного ввода ника нет.
- Капитан создаёт пустую команду: название, Telegram и Discord. Профиль игрока капитану нужен только если он сам играет. Телефон и email не запрашиваются.
- Общая ссылка приглашения: каждый игрок входит через свой Telegram, сохраняет игровой профиль и вступает сам. Капитан может дополнительно зарезервировать место по ID; игрок затем подтверждает его через ту же общую ссылку.
- Сбор состава и подача заявки разделены. Капитан подаёт команду, когда основной состав собран и все игроки вошли. Только после подачи становятся доступны взносы; допуск требует проверки состава и оплат.
- Отдельная непредсказуемая личная ссылка каждого игрока: подтверждение участия, сумма, код взноса и статус.
- Взнос **2 200 ₸ за каждого обязательного платного участника**. Для запасных правило задаётся организатором до открытия регистрации. Бесплатный запасной явно отображается как «Взнос не требуется».
- Кабинет капитана: приглашение, состав, статусы игроков/взносов и подача команды. Кабинет игрока: состав и собственная страница участия, без чужих личных ссылок и финансовых данных.
- Защищённая панель организатора: сверка платежей, проверка состава, допуск/отклонение команды с причиной, параметры турнира, расписание и результаты.
- Двойная олимпийская сетка при любом числе допущенных команд от 2 до лимита турнира. Свободные проходы явно отмечены, не создают счёта или поражения; матчи BO, переходы и повторный гранд-финал учитываются автоматически.
- Telegram: очередь заявок, подтверждение после сверки и ввода номера банковской операции, отказ с причиной, восстановление после перезапуска и сетевые повторы.
- Журнал: предыдущий/новый статус, номер операции, кто и когда проверил. Одна операция не может оплатить двух игроков. Старые кнопки и повторные запросы не подтверждают новый взнос.
- Страницы участника и капитана автоматически обновляются при изменении статуса (проверка каждые 15 секунд, пока вкладка видима и фокус не находится в поле ввода). Если редактируете форму, завершите ввод и уберите фокус из поля, чтобы проверка возобновилась.

Сетка строится до ближайшей степени двойки фактического числа допущенных команд; свободные места распределяются детерминированно. Очерёдность команд определяется созданием заявки, это не спортивный рейтинг. Пустая ветвь не считается сыгранным матчем. Перезапись сыгранных результатов блокируется, чтобы не повредить следующие матчи.

До конца регистрации капитан может вернуть ожидающую проверки заявку на редактирование с указанием причины, исправить название и Telegram/Discord, обновить общую ссылку (старая сразу перестаёт работать), сменить роль неоплаченного участника и подать команду заново. Смена основного игрока на запасного проверяет лимиты и меняет только ещё не заявленный к оплате взнос. Игрок может выйти из черновика без финансовой истории. Допущенную команду капитан сам не редактирует.

Организатор может вывести участника для замены до конца регистрации и создания сетки, включая уже оплатившего. Старое участие архивируется с причиной, автором и датой; личная страница, платёж и журнал сохраняются. Архивное место не занимает слот, не участвует в проверке допуска и не принимает новые взносы. Новый игрок получает отдельное место и взнос; деньги автоматически не переносятся и не возвращаются. Допуск команды сбрасывается, состав подаётся и проверяется заново. Отклонённая команда возвращается на сбор отдельным решением организатора.

## Реальный турнир: что нужно подтвердить

В отдельной реальной базе `tournament.sqlite3` сохранён **черновик реального турнира** по предоставленным материалам. Ограничения ниже относятся к нему; тестовая регистрация открыта:

- MLBB, 5 основных игроков, 16 команд, двойная олимпийская система;
- дата по плану совещания: 14 ноября 2026 года;
- 150 000 ₸ — обсуждавшийся, пока не подтверждённый фонд.

Организатор должен заполнить: количество и оплату запасных, форматы матчей/финала, правило повторного финала, часовой пояс, время начала и окончание регистрации, регламент и распределение призов. Затем включить «Условия подтверждены» и «Открыть регистрацию» в настройках турнира. Пустые значения показаны как «Уточняется», а сервер запрещает обход закрытой регистрации.

Сначала сохраните часовой пояс IANA, затем вводите местные часы начала/регистрации. До задания пояса формы используют UTC. Дата турнира и время начала должны совпадать в выбранном поясе. Пока участники только собирают черновые составы и финансовых действий нет, можно уточнять условия без уменьшения лимитов ниже уже занятых мест. Правило оплаты запасных блокируется после добавления запасного; после подачи команды или появления платёжной истории параметры состава и взносов менять нельзя.

## Оплата

Ссылка организатора: https://pay.kaspi.kz/pay/xd308jri (CQC.kz, ИП CQC KZ). Это обычная ссылка Kaspi Pay, **не API и не автоматическая проверка банка**.

На странице платного участника указан взнос 2 200 ₸ и код CQC. Ссылка открывает QR на компьютере или предложение перейти в приложение Kaspi.kz на мобильном устройстве. На проверенной веб-странице нет поля суммы; ввод суммы и наличие комментария внутри приложения пока не проверены. Если приложение позволяет добавить комментарий, укажите код CQC и никнейм. Если такого поля нет, сохраните код и банковский чек для ручной сверки с организатором.

После фактического перевода вернитесь на свою страницу и нажмите «Я оплатил»: это создаёт только статус «На проверке». Открытие ссылки не передаёт сайту подтверждение банка и не меняет статус взноса. Кассир сопоставляет фактическое поступление в Kaspi Pay с участником и суммой, использует код CQC для поиска заявки, вводит уникальный номер банковской операции и подтверждает решение. Скриншот участника и уведомление сами по себе не считаются подтверждением. В тестовом режиме вместо перевода используется кнопка «Отправить тестовый взнос на проверку», а решение принимается в панели организатора с уникальным тестовым номером операции.

Четыре статуса: «Ожидает оплаты», «На проверке», «Оплата подтверждена», «Отклонена». После отказа игрок может подать взнос на повторную проверку. Допуск команды требует подтверждения участия каждого заявленного игрока, проверки состава и всех обязательных платежей.

Отказ команде не означает возврат денег: уже поступившие оплаты и история сохраняются. Возвраты отложены и выполняются человеком в Kaspi Pay. Снимок QR возврата сохранён только как справочный артефакт и не используется для приёма взносов.

`arena/providers.py` отделяет создание страницы оплаты от будущей проверки официального провайдера. Для API нужны отдельное подтверждённое подключение и документация Kaspi, проверка подлинности серверного события, суммы/валюты/получателя/номера операции и защита от повторов. Сейчас нет обхода API через ADB, перехвата трафика, автоматизации банковского интерфейса или интеграции Smile.one.

## Telegram и проверка игрового ника

На странице входа выберите Telegram. Сайт создаёт запрос на 10 минут и показывает отдельный шестизначный код. Откройте бота по кнопке, ответьте кодом на его сообщение, подтвердите вход в боте, затем вернитесь в исходный браузер и подтвердите показанный Telegram-профиль. Код вводится в боте турнира, это не код входа в сам Telegram. Одна пересланная ссылка не даёт войти. Повторное завершение, другой браузер и больше пяти ошибочных попыток блокируются. Новая учётная запись не получает прав организатора, даже если её Telegram ID совпадает с кассиром.

Основной путь: капитан создаёт команду → копирует общую ссылку → игрок открывает её и входит через Telegram → находит свой аккаунт по ID/серверу → сохраняет → возвращается к приглашению и вступает. Приглашение сохраняется во время входа и заполнения профиля. Капитан не вводит анкеты остальных. Пока есть действующее участие, изменение профиля заблокировано; после выхода/архивирования исторические данные остаются отдельным снимком. Сообщить об оплате может только связанный действующий участник после подачи команды.

Если ID занят, в игровом профиле есть ссылка «Обратиться к организатору». Заявитель указывает пару ID/сервер и объяснение; ник получается через lookup. Организатор рассматривает обращение в отдельной очереди, проверяет владение в игре и записывает решение с причиной. Старые привязки проверяются повторно перед изменением: решение по устаревшему состоянию блокируется. При действующих местах в составе сначала нужен отдельный разбор/вывод участника. Переносится только игровой профиль; исторические участия, Telegram-аккаунты и платежи не передаются другому человеку. Решение нельзя повторить или переписать. Чужие персональные данные заявителю не показываются.

В профиле введите только Game ID и Server ID и нажмите «Найти аккаунт». Сайт покажет найденный ник; после проверки поставьте отметку «Это мой игровой аккаунт» и сохраните. Поиск и сохранение обновляют карточку без перезагрузки страницы и сохраняют прокрутку; переход обратно к приглашению выполняется отдельной ссылкой. Результат поиска действует 10 минут, связан с пользователем и парой ID/сервер; изменение ID требует нового поиска. Сохранение использует уже показанный результат и не делает второго запроса к провайдеру.

**Автопроверка ника через GoPay включена** в локальной конфигурации (`MLBB_LOOKUP_PROVIDER=gopay`). Проверка предоставленной пользователем пары ID + Server ID успешно вернула ник. Ранее публичный пример также вернул ник, а неправильный сервер был отклонён. Это сторонний сервис, а не официальный developer API Moonton. Подробности и первичные источники: [docs/API_RESEARCH.md](docs/API_RESEARCH.md).

Для GoPay ключ не требуется. Подготовленный альтернативный адаптер MooGold требует партнёрские доступы и подтверждённые параметры продукта; эти требования не относятся к найденному GoPay lookup.

Без работающего провайдера поиск и сохранение нового игрового профиля недоступны; ручного обхода нет. Ни найденный ник, ни вход в Telegram не доказывают владение игровым аккаунтом. Это проверяет организатор при проверке состава. В `.env.example` перечислены настройки; `MLBB_LOOKUP_PROVIDER=disabled` — безопасное исходное состояние до подключения. Проверка ника не создаёт покупок или пополнений.

Для локального входа домен не требуется: сайт опрашивает свою базу, бот получает обновления через Bot API. При публикации задайте актуальный `PUBLIC_BASE_URL` и `TELEGRAM_BOT_USERNAME`. Ежедневно выполняйте `manage.py clearsessions`; истёкшие запросы входа не дают авторизоваться и могут удаляться по политике хранения.

## Проверки

```powershell
.\.venv\Scripts\python.exe manage.py check
$env:TOURNAMENT_DEMO_MODE='0'
.\.venv\Scripts\python.exe manage.py test arena --noinput
Remove-Item Env:TOURNAMENT_DEMO_MODE
```

Тесты создают отдельную временную базу и имитируют Telegram: реальные платежи и сообщения кассиру не отправляются. Проверяются права, CSRF, подмена сумм/ролей, повторные операции, устаревшие кнопки, очередь и турнирная сетка. Визуальные снимки для 390px и 1440px — `artifacts/qa/`.

## Что понадобится для публикации

Резервную копию текущей базы можно создать командой `.\.venv\Scripts\python.exe manage.py backup_database`. Она проверяет целостность и не перезаписывает существующие файлы. Порядок проверки восстановления и переключения на восстановленную базу: [docs/BACKUP_RESTORE.md](docs/BACKUP_RESTORE.md). Автоматическое расписание копирования пока не включено.

1. Подтверждённый регламент и параметры турнира; рабочая ссылка Kaspi и ответственный кассир.
2. Для опубликованной версии уже настроены Vercel, HTTPS и Supabase PostgreSQL; инструкция — [docs/VERCEL_DEPLOYMENT.md](docs/VERCEL_DEPLOYMENT.md). SQLite остаётся только локальным вариантом и не размещается на эфемерном диске Vercel.
3. Настройки окружения: `DJANGO_DEBUG=0`, `DJANGO_ALLOWED_HOSTS=ваш.домен`, `DJANGO_CSRF_TRUSTED_ORIGINS=https://ваш.домен`, `PUBLIC_BASE_URL=https://ваш.домен`, отдельный случайный `DJANGO_SECRET_KEY`, Telegram-токен и ID кассира. Секреты не включать в репозиторий/архивы исходников.
4. HTTPS reverse proxy и корректная передача защищённой схемы. `SECURE_PROXY_SSL_HEADER` намеренно не доверяет произвольным прокси: задайте его только для контролируемого reverse proxy, который удаляет входящий заголовок клиента и сам устанавливает `X-Forwarded-Proto`.
5. `migrate`, `collectstatic`, `check --deploy`; смена локального пароля организатора, сервисы с автоперезапуском, резервное копирование SQLite через SQLite backup API, ротация и проверка восстановления резервных копий.
6. Согласованные организатором контакт поддержки, условия участия/отказа/возврата и обработка персональных данных. Личные ссылки игроков дают доступ к их странице — их нужно передавать только соответствующим участникам.

Лимитер хранится в общей базе и поддерживает несколько экземпляров приложения. Настройте журналы HTTP без полных личных URL участников; приложение не подключает стороннюю аналитику и использует `Referrer-Policy: same-origin`.

Проверка `check --deploy` с отключённым DEBUG оставляет рекомендации HSTS для всех поддоменов и HSTS preload. Включайте их только после выбора домена и подтверждения HTTPS для всех затронутых поддоменов. Результаты технических и браузерных проверок: [docs/QA.md](docs/QA.md).

## Структура

`arena/models.py` — база; `services.py` — платежи и допуск; `team_services.py`/`team_views.py` — сбор состава и приглашения; `bracket.py` — сетка; `views.py`/`forms.py` — сайт; `telegram.py` — кассир; `providers.py` — граница платёжной интеграции; `templates/`/`static/` — интерфейс; `.local/` — локальная база, доступ и журналы (не Git).
